# How to run the Performance Dashboard

**App:** PAM Performance Dashboard (`OBJ-019`) · **Location:** `tools/dashboard-performance/`
**Stack:** React 18 + Vite 5 + Recharts. No backend — datasets are static JSON fetched at runtime.

This is a sibling of the API dashboard (`tools/dashboard/`). The two are independent and run at the
same time on different ports. Manual steps for the API app are at the bottom.

---

## 1. Prerequisites

| Need | Version | Check |
|---|---|---|
| Node.js | 18 or newer (verified on **v24.19.0**) | `node --version` |
| npm | 9 or newer (verified on **11.18.0**) | `npm --version` |

Both are already installed on this machine. Nothing else is required — no Java, no k6, no database.

---

## 2. First-time install (once)

From a terminal:

```powershell
cd "E:\Omkar\Automation\Dev Project\workbench\react-performance"
npm install
```

This creates `node_modules/` (gitignored). It takes ~15 seconds. You only do this once, or again
after `package.json` changes.

---

## 3. Start it

```powershell
cd "E:\Omkar\Automation\Dev Project\workbench\react-performance"
npm run dev
```

- It prints a line like `Local: http://localhost:5174/` and **opens your browser automatically**.
- **Default URL:** <http://localhost:5174/>  (port **5174** — the API dashboard uses 5173, so both
  can run together.)

## 4. Stop it

In the terminal where it is running, press **`Ctrl + C`** (and answer `Y` if asked). That is all.

## 5. Restart it

Just run `npm run dev` again. If it says the port is in use, either an instance is already running
(open <http://localhost:5174/>) or stop the old one first:

```powershell
# find and stop whatever holds port 5174
Get-NetTCPConnection -LocalPort 5174 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

---

## 6. Environment variables / configuration

**None required.** The app reads its datasets from `public/data/*.json` at runtime. There is no API
key, no `.env`, no server config.

To change the port, edit `server.port` in `vite.config.js`.

---

## 7. The data — sample now, real later

Right now every latency/throughput figure is **SAMPLE data** (a standing amber banner says so on
every page). The Sanity scope — 13 modules, 211 checks — is real, read from the framework's own
`performance/data/sanity-modules.json`.

To regenerate the datasets:

```powershell
cd "E:\Omkar\Automation\Dev Project\workbench\react-performance"
node scripts\build-performance-data.mjs
```

When a real k6 execution has produced results (`performance/reports/<runId>/`), point the generator's
`INGEST_RUN` at that folder; `dataState` flips to `measured`, the sample banner disappears, and the
dashboard shows real numbers. **The React code does not change** — only the generator and the JSON.

---

## 8. Build a static copy (optional)

```powershell
npm run build      # writes dist/
npm run preview    # serves dist/ at http://localhost:4174/ to check it
```

`dist/` opens from the filesystem too (hash routing, no server rewrite needed).

---

## 9. Troubleshooting

| Symptom | Fix |
|---|---|
| `npm run dev` fails, "vite not recognised" | You skipped step 2 — run `npm install` first. |
| Browser shows "Could not load the performance datasets" | The `public/data/*.json` files are missing — run `node scripts\build-performance-data.mjs`. |
| Port 5174 already in use | An instance is already running (open the URL), or stop it with the command in §5. |
| Charts look empty | Hard-refresh the browser (`Ctrl+Shift+R`) — a cached old dataset. |
| Blank page, console errors | Check the terminal running `npm run dev` for the real error; re-run `npm install` if a dependency is missing. |
